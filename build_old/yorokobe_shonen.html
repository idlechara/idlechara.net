Yorokobe Shonen !
Not too long ago (August 14th - 2017) talking with @cryofrzd about ideas for my thesis project we came across multiple uses for the phrase "Yorokobe shonen" (喜べ少年), which is commonly said by Kotomine Kirei (Fate Series). This phrase can be translated as "Rejoice, my boy" with an air that express some kind of relief because you're on the right path. So we joked around common phrases (and mistakes) which coders do. The phrases are as follows:



Yorokobe Shonen, we don't do include guards, cause we never include twice.

Yorokobe Shonen, we follow the mathematical notation when writing functions, the variables are x, y, z, X, Y, Z, xprime, yprime, dYdx etc. If the variable isn't passed in the math notation, it's passed by being a global variable.

Yorokobe Shonen, we include Object Relational Mappers only to use bare SQL sentences to get the data.

Yorokobe Shonen, we import Apache, to read a file to a string.

Yorokobe Shonen, we raise a web service for a standalone desktop application.

Yorokobe Shonen, What do you mean closing pipes/files/exiting processes?

Yorokobe Shonen, there is nothing wrong with stray pointers.

Yorokobe Shonen, import/include compiletime/preprocesor instructions resolve loops automatically so you dont need to check them.

Yorokobe Shonen, extern function declaration without a makefile. i.e. no header file.

Yorokobe Shonen, more threads -> more speed.

Yorokobe Shonen, A thread per row in matrix multiplication with channels to get the column.

Yorokobe Shonen, Threads are lightweight.

Yorokobe Shonen, Processes instead of threads.

Yorokobe Shonen, Using text files as FIFO to communicate two processes.

Yorokobe Shonen, the more forks on the plates the better, my concurency policy.
